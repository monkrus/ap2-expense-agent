═══════════════════════════════════════════════════════════════
 👤 ROLE CAPABILITIES
═══════════════════════════════════════════════════════════════

🟢 EMPLOYEE
-----------
Purpose: Submit and track personal expenses

Can:
  ✅ Submit expenses
  ✅ View/edit/delete own expenses (pending only)
  ✅ Withdraw pending expenses
  ✅ Upload receipts
  ✅ Add comments to own expenses
  ✅ View own reports

Cannot:
  ❌ Approve/reject expenses
  ❌ View other users' expenses
  ❌ Access admin features


🟡 MANAGER
----------
Purpose: Oversee department expenses and approvals

Can (All employee permissions +):
  ✅ View ALL expenses (full visibility for planning & oversight)
  ✅ Approve/reject department expenses (up to $5,000 only)
  ✅ Bulk approve/reject (≤$5,000 per expense)
  ✅ View department reports
  ✅ Export reports
  ✅ See high-value expenses with "Admin Approval Required" indicator

Cannot:
  ❌ Approve own expenses (self-approval prevention)
  ❌ Approve expenses over $5,000 (requires admin)
  ❌ Approve expenses from other departments (when departments set)
  ❌ Manage users or change roles
  ❌ Access system settings

Approval Limit: $5,000 per expense
Visibility: Can VIEW all expenses, but can only APPROVE ≤$5,000
Department Scope: Can only approve expenses from their department (when set)


🔴 ADMIN
--------
Purpose: System administration and user management

Can:
  ✅ ALL permissions (superuser)
  ✅ Approve expenses of any amount
  ✅ Approve expenses from any department
  ✅ Manage users via User Management Dashboard:
      • Create new user accounts (email, username, password, role, department)
      • Edit user roles (EMPLOYEE, MANAGER, ADMIN)
      • Assign users to departments for filtering
      • Suspend/activate user accounts
      • Delete user accounts (with self-protection)
      • View user permissions by role
  ✅ Configure system settings
  ✅ Perform database maintenance
  ✅ Access all data

No restrictions

Admin Dashboard Features:
  📊 Three-tab interface:
     1. Pending Approvals - Review and approve/reject pending expenses
     2. All Expenses - View all expenses with status filtering
     3. User Management - Complete CRUD operations for user accounts

═══════════════════════════════════════════════════════════════
 🔄 EXPENSE WORKFLOW
═══════════════════════════════════════════════════════════════

1. SUBMISSION (Employee)
   └─> Status: PENDING
       └─> Email sent to employee (confirmation)
       └─> Email sent to all managers/admins (notification)

2. APPROVAL PROCESS
   ├─> Manager reviews (if amount ≤ $5,000 and same department)
   │   ├─> APPROVE → Status: APPROVED
   │   │   └─> AP2 transaction created
   │   │   └─> Email sent to employee
   │   │   └─> Audit trail created
   │   │
   │   └─> REJECT → Status: REJECTED
   │       └─> Rejection reason required
   │       └─> Email sent to employee
   │
   └─> Admin reviews (if amount > $5,000 or different department)
       ├─> APPROVE → Status: APPROVED
       └─> REJECT → Status: REJECTED

3. EMPLOYEE ACTIONS
   ├─> Edit (if PENDING)
   ├─> Withdraw (if PENDING) → Status: WITHDRAWN
   └─> Add comments (any time)


═══════════════════════════════════════════════════════════════
 🔐 SESSION MANAGEMENT & CONCURRENT LOGIN LIMITS
═══════════════════════════════════════════════════════════════

The application enforces role-based concurrent session limits to balance security
and user convenience. When a user exceeds their session limit, the oldest session
is automatically revoked.

CONCURRENT SESSION LIMITS BY ROLE:

🟢 EMPLOYEE (1 Session Limit)
  - Can only be logged in on ONE device at a time
  - Logging in from a new device/browser will log out the previous session
  - Use case: Single workstation access for security
  - Example: If logged in on Desktop, logging in on Mobile will log out Desktop

🟡 MANAGER (2 Sessions Limit)
  - Can be logged in on up to TWO devices simultaneously
  - Common scenario: Desktop at office + Mobile device
  - 3rd login will automatically revoke the oldest session
  - Example: Desktop + Mobile = OK, Desktop + Mobile + Tablet = Desktop logged out

🔴 ADMIN (Unlimited Sessions)
  - No session limit - can log in from unlimited devices
  - Maximum flexibility for system administrators
  - Example: Desktop + Laptop + Mobile + Tablet = All stay logged in

HOW IT WORKS:

1. User logs in from Browser/Device A
   └─> Session 1 created

2. User logs in from Browser/Device B (while still logged in on A)
   └─> Session 2 created
   └─> For EMPLOYEE: Session 1 is revoked (logged out)
   └─> For MANAGER: Both sessions remain active
   └─> For ADMIN: Both sessions remain active

3. Manager logs in from Browser/Device C (while logged in on A & B)
   └─> Session 3 created
   └─> Session 1 (oldest) is automatically revoked
   └─> Sessions 2 and 3 remain active

TECHNICAL DETAILS:

- Sessions expire after 24 hours of inactivity
- Revoked sessions cannot be reused (user must log in again)
- Session revocations are logged in the audit trail
- Action: "session.auto_revoked"
- Each session tracks: IP address, User-Agent, creation time
- JWT access tokens expire after configured time (default: 15 minutes)
- Refresh tokens are used to obtain new access tokens

SECURITY NOTES:

- Session limits help prevent unauthorized account sharing
- Audit logs track all session creations and revocations
- Users can manually revoke sessions from their account settings
- Admins can view and revoke user sessions via User Management Dashboard

 👥 ADMIN USER MANAGEMENT DASHBOARD
═══════════════════════════════════════════════════════════════

The Admin Dashboard includes a dedicated User Management tab for complete
user account administration.

ACCESS:
  1. Login as admin (admintest / password)
  2. Navigate to Admin Dashboard
  3. Click "User Management" tab

FEATURES:

📊 User Overview:
  - Total users count
  - Active users count
  - Role breakdown (Admins, Managers, Employees)
  - Search by name, email, or username
  - Filter by role (All, Employee, Manager, Admin)

➕ CREATE NEW USER:
  1. Click "Create New User" button
  2. Fill in the form:
     • Email address (must be unique)
     • Username (must be unique)
     • Full name
     • Password (bcrypt hashed)
     • Role (EMPLOYEE, MANAGER, ADMIN)
     • Department ID (optional, for manager filtering)
  3. Click "Create User"
  4. User is created with is_verified=true (pre-verified)

✏️ EDIT USER:
  1. Click "Edit" button on any user row
  2. Modify:
     • Role (upgrade/downgrade permissions)
     • Department assignment
     • Active status (suspend/activate account)
  3. Click "Save Changes"
  4. Audit log created automatically

🗑️ DELETE USER:
  1. Click "Delete" button on any user row
  2. Confirm deletion
  3. User account is permanently removed
  4. Self-protection: Cannot delete own account
  5. Audit log created automatically

🔍 VIEW PERMISSIONS:
  1. Click "View Permissions" button
  2. See all permissions granted to that user's role
  3. Permissions are based on RBAC system (50+ permissions)

SECURITY FEATURES:
  ✅ Admin-only access (requires ADMIN role)
  ✅ Self-delete protection (cannot delete own account)
  ✅ Email/username uniqueness validation
  ✅ Password hashing with bcrypt
  ✅ Complete audit trail for all operations
  ✅ Real-time user count and statistics
  ✅ Search and filter capabilities

AUDIT LOGGING:
  All user management operations are logged:
  - admin.create_user - New user created
  - admin.update_user_role - Role changed
  - admin.update_user_department - Department assigned
  - admin.suspend_user - Account suspended
  - admin.activate_user - Account reactivated
  - admin.delete_user - Account deleted

═══════════════════════════════════════════════════════════════
 🛠️ TROUBLESHOOTING
═══════════════════════════════════════════════════════════════

Problem: Backend won't start
Solution:
  1. Check if port 8000 is already in use:
     netstat -ano | findstr :8000  (Windows)
     lsof -i :8000  (Mac/Linux)

  2. Kill the process or use a different port:
     .venv\Scripts\python.exe -m uvicorn src.api:app --port 8001 --reload

Problem: Frontend won't start
Solution:
  1. Check if port 5173 is in use
  2. Delete node_modules and reinstall:
     cd frontend
     rmdir /s /q node_modules  (Windows)
     rm -rf node_modules  (Mac/Linux)
     npm install

Problem: "Permission denied" errors
Solution:
  Check user role and permissions:
  - Managers can only approve ≤ $5,000
  - Users cannot approve own expenses
  - Managers can only approve their department (when departments set)

Problem: Email notifications not working
Solution:
  1. Check SMTP settings in backend/.env:
     SMTP_SERVER=smtp.gmail.com
     SMTP_PORT=587
     SMTP_USERNAME=your-email@gmail.com
     SMTP_PASSWORD=your-app-password
     NOTIFICATIONS_ENABLED=true

  2. For Gmail, create an App Password:
     https://myaccount.google.com/apppasswords

Problem: Tests failing
Solution:
  cd backend
  .venv\Scripts\python.exe -m pytest tests/test_permissions.py -v
